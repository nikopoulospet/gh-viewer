gh-viewer

Saved queries

Each query is a GraphQL document plus variables. List path points at the array to render (e.g. search.nodes); several comma-separated paths are merged and deduped. Count path is optional and only feeds the status line. Rows drill down by node id, so keep id in the selection.

GitHub App

gh-viewer ships with its own App, so there is nothing to fill in here. Override the Client ID only to point at an App you registered yourself; clearing the field restores the built-in one. It is a public identifier either way — gh-viewer holds no secret.

What gh-viewer can read

Your own work always shows up. Once you are signed in, issues and pull requests in public repositories and in repositories you own need nothing further — no install, and nobody else's approval.

An organisation's private repositories are the part that needs more. gh-viewer reads them through a GitHub App, which sees an organisation only where it has been installed — and that is configured once for the whole organisation, by someone who administers it, covering everyone in it afterwards.

Adding an organisation

Only needed to reach an organisation's private repositories, and only if that organisation is missing from the list above — which means the App is not installed on it yet. This is a one-time step for the whole organisation, not something each person repeats.

  1. Open the gh-viewer install page on GitHub.
  2. Pick the organisation, then choose all repositories or a hand-picked few. If you administer it, that installs it for everyone. If you do not, GitHub turns it into a request for an owner to approve — once, for the whole organisation.
  3. Come back here and press Check access to confirm.

GitHub documents this flow in Installing a GitHub App from a third party.

Already installed but still missing a repository? Then the installation is scoped to a few repositories rather than all of them, and an owner needs to add yours — the same page, under Repository access.

Export state

A snapshot of how gh-viewer is configured and what it can reach, for attaching to a bug report.

Included: extension version and permissions, browser user agent, which App and Client ID are in use, whether you are signed in, and your saved queries with their variables. Never included: your access token — only whether one exists and what kind it is.
